How to use this course

Accessibility is not a collection of technical tricks. It starts by asking whether people can perceive information, understand what is happening, navigate, act, recover from mistakes, and complete their goal.

The activities below deliberately use everyday situations. You do not need to know any particular technology to answer them.

After each activity, the How to test section explains how the same principle can be checked in five different contexts.

Module 1

Content and alternatives

Make sure important information is available in a form people can perceive and use.

Learn

Not every visual, sound, or other non-text element needs the same treatment. First ask what role it plays: is it decorative, informative, functional, or carrying complex information?

Observe

Scenario:

A travel service shows four visual elements:

  1. A decorative line separating two sections.
  2. A photograph showing a damaged suitcase.
  3. An icon that starts a journey-planning action.
  4. A complex chart showing changes over several months.

Identify

Classify each element. Choose the best description.

Understand

The correct question is not “Does this image have a description?” The useful question is “What information or purpose would be lost if this element could not be perceived?”

Manipulate

Imagine the journey-planning icon disappears. What should remain possible?

How to test this principle

Web

  1. Look at every meaningful image or visual element.
  2. Ask what information or action it provides.
  3. Check that equivalent information is available without depending on the visual.
  4. Check decorative visuals do not introduce unnecessary information.
  5. For complex visuals, check that the important message can be understood another way.

iOS

  1. Move through the screen using the available accessibility navigation.
  2. Check that meaningful images and controls communicate their purpose.
  3. Check that decorative images do not interrupt the useful content.
  4. For complex visuals, verify that their essential message is available elsewhere.

Android

  1. Inspect each meaningful image and visual control.
  2. Check that its purpose or information is exposed clearly.
  3. Check decorative images are not presented as meaningful content.
  4. Check complex visual information has an equivalent explanation.

Office documents

  1. Review every informative image, chart, or illustration.
  2. Check that its purpose is described appropriately.
  3. Check decorative images are treated as decorative.
  4. Check charts and complex graphics have an understandable equivalent.

Design mockups

  1. Annotate every non-text element as decorative, informative, functional, or complex.
  2. Specify the intended alternative for informative and functional content.
  3. Identify complex graphics that need an additional explanation.
  4. Check that important text is not planned only inside an image.
Module 2

Structure and relationships

Make the organisation of information understandable.

Learn

People should be able to understand what belongs together, what comes first, what is a main topic, and what is a detail. Visual appearance alone should not be the only clue.

Interact: repair the structure

A help article has these sections:

Choosing a replacement
Returning a damaged item
Getting help

Decide

Which organisation is easiest to follow?

Understand

Good structure reduces the amount of interpretation people must perform. A clear visual hierarchy should correspond to the underlying organisation of the content.

How to test this principle

Web

  1. Check that headings form a logical hierarchy.
  2. Check that the page has a clear main topic and meaningful sections.
  3. Check that the reading order follows the intended meaning.
  4. Check that visual layout does not create a misleading order.

iOS

  1. Move through the screen and check whether the order remains understandable.
  2. Check that headings and groups communicate the organisation of the screen.
  3. Check that related information is kept together.

Android

  1. Check the order in which content is encountered.
  2. Check that related elements are grouped meaningfully.
  3. Check that important sections can be distinguished clearly.

Office documents

  1. Check document headings and their hierarchy.
  2. Check reading order.
  3. Check that lists, tables and groups are structurally meaningful.

Design mockups

  1. Identify the intended main heading and section hierarchy.
  2. Annotate the reading order when the visual layout could make it ambiguous.
  3. Identify groups that must remain related.
Module 3

Perception: colour, contrast and non-colour cues

Make information distinguishable without relying on colour alone.

Observe

Manipulate

Improve this message without changing its meaning:

Fields shown in red contain errors.

How to test this principle

Web

  1. Inspect important text and background combinations.
  2. Check that important distinctions remain understandable without colour.
  3. Check that interactive and focus indicators remain visible.

iOS

  1. Check text and important controls in normal and alternate display conditions.
  2. Check that colour is not the only way to identify a state.
  3. Check that focus or selection remains visible.

Android

  1. Check text and control visibility.
  2. Check important states without relying only on colour.
  3. Check visibility of selected, focused and error states.

Office documents

  1. Inspect text/background combinations.
  2. Check that meaning does not depend only on colour.
  3. Check charts, tables and highlighted information for sufficient distinction.

Design mockups

  1. Check planned text contrast.
  2. Check interactive-state contrast and visible focus.
  3. Check that colour is accompanied by another cue when it carries meaning.
  4. Check informative illustrations and charts for sufficient distinction.
Module 4

Adaptation and readability

Ensure content remains usable when text becomes larger or available space becomes smaller.

Interact with the layout

Reading area

This is an important service message. The complete sentence should remain available and understandable when the reading conditions change.

Change the conditions and observe what happens. Look for information that becomes hidden, overlaps, or becomes unnecessarily difficult to use.

Understand

Adaptation is successful when changing the presentation conditions does not destroy meaning or make ordinary use unnecessarily difficult.

How to test this principle

Web

  1. Increase text size substantially.
  2. Check that text is not clipped or overlapped.
  3. Check that controls remain usable.
  4. Reduce the available width and check that content adapts.

iOS

  1. Increase the system text size.
  2. Inspect long labels, buttons, forms and messages.
  3. Check for clipping, overlap or loss of information.
  4. Check the layout in different orientations when supported.

Android

  1. Increase the system text size.
  2. Inspect content, controls and forms.
  3. Check for clipping or overlap.
  4. Check that the layout adapts to available space.

Office documents

  1. Enlarge text or change the viewing conditions.
  2. Check that information remains readable and ordered.
  3. Check tables and long content for loss or unnecessary difficulty.

Design mockups

  1. Review the design with larger text.
  2. Check that content does not overlap or disappear.
  3. Review narrow layouts and planned responsive behaviour.
  4. Check that two-direction scrolling is not unnecessarily required.
Module 5

Navigation and operation

Let people move through an experience and know where they are.

Scenario

You are completing a four-step application:

One version of the process unexpectedly sends you from step 2 back to step 1 without explaining why.

Challenge

Which problems should you look for during a navigation test?

How to test this principle

Web

  1. Complete the main journeys without getting stuck.
  2. Check the order in which interactive elements are encountered.
  3. Check that there are no places where navigation becomes trapped.
  4. Check that the current position remains understandable.

iOS

  1. Complete the main journeys using the available navigation methods.
  2. Check the order of interactive elements.
  3. Check that no part of the journey becomes inaccessible.
  4. Check that the current screen and state remain understandable.

Android

  1. Repeat the main user journeys.
  2. Check navigation order and focus movement.
  3. Check for traps or inaccessible controls.
  4. Check that changes in position remain understandable.

Office documents

  1. Check the document reading order.
  2. Check navigation between sections and references.
  3. Check that the person can move through the document without unexpected jumps.

Design mockups

  1. Annotate the intended reading and interaction order.
  2. Identify non-standard components requiring a specific interaction rule.
  3. Check that no essential information appears only after a particular pointer action.
  4. Document any potentially ambiguous navigation sequence.
Module 6

Actions and interaction

Make it clear whether something leads somewhere or changes something.

Sort the intentions

Select an item, then choose whether its purpose is “go to information” or “perform/change something”.

Improve the wording

Which is clearer?

How to test this principle

Web

  1. Check that each interactive element has a clear purpose.
  2. Check that destinations and actions are distinguishable.
  3. Check that repeated elements can be distinguished by context.
  4. Check that interactive elements have adequate usable areas and clear states.

iOS

  1. Check the purpose of each interactive element.
  2. Check that actions are distinguishable from navigation to another place.
  3. Check that interactive areas are large enough for comfortable use.
  4. Check all important interaction states.

Android

  1. Check that every interactive element communicates its purpose.
  2. Check that actions and destinations are clear.
  3. Check that touch areas are sufficiently large and separated.
  4. Check interactive states and feedback.

Office documents

  1. Check that references have meaningful wording.
  2. Check that links clearly communicate their destination.
  3. Check repeated references are distinguishable by context.

Design mockups

  1. Annotate whether each interactive element is a destination or an action.
  2. Check that visible labels are meaningful and unique when necessary.
  3. Annotate required states: hover, focus, active, disabled, error, success and loading.
  4. Specify the intended interactive area for each component.

Names, functions and states

Help people understand what something is, what it does, and what is happening.

Scenario

Imagine a control:

It represents a favourite item.

It can be selected or not selected.

When selected, the item is saved for later.

Which information should be understandable?

Fix the ambiguity

How to test this principle

Web

  1. Check that each interactive element has an understandable name or visible label.
  2. Check that its purpose is clear.
  3. Trigger each important state and check that the change is communicated.
  4. Check dynamic messages and status changes.

iOS

  1. Inspect interactive elements with the available accessibility tools.
  2. Check their names and purposes.
  3. Check selected, disabled, expanded, loading and other relevant states.
  4. Check that important changes are communicated.

Android

  1. Inspect interactive elements using the available accessibility tools.
  2. Check names and purposes.
  3. Check important states and state changes.
  4. Check dynamic messages.

Office documents

  1. Check that headings, links, tables and other meaningful objects are identifiable.
  2. Check that their purpose is understandable from context.
  3. Check important document states and fields where applicable.

Design mockups

  1. Give every interactive component a meaningful name.
  2. Annotate its purpose when the visible label is insufficient.
  3. Specify all relevant states: focus, active, disabled, error, success and loading.
  4. Check that state changes are visually and semantically understandable.
Module 8

Forms, instructions and recovery

Help people complete tasks and recover when something goes wrong.

Complete the form

Choose the better error message

Understand

A good form tells people what information is expected, identifies what needs attention, explains the problem, and helps them recover.

How to test this principle

Web

  1. Check that every field has a meaningful label.
  2. Check how required fields are identified.
  3. Submit incomplete and incorrect information.
  4. Check that errors identify the relevant field and explain the problem.
  5. Check that the person can recover without losing useful information.

iOS

  1. Check labels and instructions for every field.
  2. Check required and optional information.
  3. Enter incorrect or missing information.
  4. Check that errors are understandable and associated with the right field.

Android

  1. Check field labels and instructions.
  2. Check required fields.
  3. Test missing and invalid information.
  4. Check that error feedback is clear and actionable.

Office documents

  1. Check form fields have meaningful labels.
  2. Check required information and expected formats.
  3. Trigger validation errors where possible.
  4. Check that error messages are understandable and associated with the relevant field.

Design mockups

  1. Give every field a visible, relevant label.
  2. Define how required fields will be identified.
  3. Design the error state for every field that can fail.
  4. Ensure the error identifies the field and explains how to recover.

Module 10

Changes, motion and media

Help people understand changing information and time-based content.

Simulation

A dashboard automatically changes its main message every few seconds.

Message 1: Delivery scheduled.

What should a person be able to do?

Plan the alternatives

How to test this principle

Web

  1. Check automatically changing content.
  2. Check whether the person can pause or stop it where necessary.
  3. Check captions and transcripts for relevant media.
  4. Check audio description when important visual information is not otherwise available.
  5. Check dynamic messages are understandable.

iOS

  1. Check moving or automatically changing content.
  2. Check available controls for pausing or stopping it.
  3. Check captions, transcripts and audio descriptions where relevant.
  4. Check important changes are communicated.

Android

  1. Check automatic changes and moving content.
  2. Check controls for pausing or stopping it.
  3. Check equivalent media information.
  4. Check dynamic status messages.

Office documents

  1. Check audio and video alternatives.
  2. Check captions and transcripts.
  3. Check audio description where required.
  4. Check that important changes or animations are not the only way information is communicated.

Design mockups

  1. Annotate pause/stop requirements for moving content.
  2. Annotate captions and transcript requirements.
  3. Annotate audio description requirements.
  4. Identify important information that must remain available without timing or animation.

Stage 2 — Choose an option

Stage 3 — Complete the information

Stage 4 — Finish the task

Final decision

Which statement best describes an accessible experience?

Audit mindset

A good accessibility review does not stop when one criterion is satisfied. Follow a real journey. Look for barriers at every stage. Ask whether a person can understand what is available, perceive the important information, navigate, act, recover from mistakes, and reach the intended outcome.

How to test this principle

Web

  1. Choose a representative user journey.
  2. Complete it from beginning to end.
  3. Repeat it using different ways of navigating and perceiving the content.
  4. Check content, structure, contrast, resizing, navigation, interaction, names, forms and dynamic changes.
  5. Record barriers according to their impact on task completion.

iOS

  1. Choose a complete journey.
  2. Repeat it using the available accessibility features.
  3. Check content, order, names, states, text size, forms and interactions.
  4. Check important changes and feedback.
  5. Verify that the task can actually be completed.

Android

  1. Choose a representative journey.
  2. Repeat it using the available accessibility features.
  3. Check content, structure, text size, forms, interaction and layout.
  4. Check important states and dynamic changes.
  5. Verify successful completion.

Office documents

  1. Choose a complete document task.
  2. Check structure and reading order.
  3. Check images, tables, lists and references.
  4. Check media alternatives when present.
  5. Use available accessibility inspection tools as a complement to manual review.

Design mockups

  1. Walk through the complete proposed journey.
  2. Check every screen for content, structure and visual perception.
  3. Check component labels and all interaction states.
  4. Check forms, errors, responsive behaviour and media requirements.
  5. Annotate anything that needs to be verified during implementation.
