1. Content and alternatives

Check that all meaningful content is available to users regardless of how it is presented.

Voici 4 images, identifiez les images décorative, porteuses de sens....

QCM

puis explications de comment tester efficacement avec des onglets par techno

Procedure

Review images, icons, graphics and other non-text content. Identify whether each visual element is decorative, informative, functional or conveys complex information. Check that meaningful visual information has an appropriate text alternative.

Review audio and video content and identify the alternatives required to understand its information, such as captions, transcripts or audio descriptions.

Check that informative text is not embedded in images when the same information can be provided as real text.

Verify

Informative images and graphics have relevant alternatives. Decorative content is correctly identified as decorative. Functional images have an accessible name that describes their purpose.

Complex graphics provide an appropriate textual description. Audio and video provide the required alternatives. Essential information is not available only visually or audibly.

Tool

Browser accessibility inspector, document accessibility checker, screen reader, NVDA, JAWS, TalkBack, VoiceOver.

Result

All meaningful information conveyed by images, graphics, audio or video is available through an appropriate accessible alternative.

Procedure

Inspect the structure of the page, screen or document. Check the page or document title, language, headings and their hierarchy, sections, paragraphs, lists, tables and other semantic structures.

Navigate through the content using an assistive technology and compare the reading order with the intended visual and logical order.

Verify

Titles identify the current page, screen or document and follow a meaningful naming convention. The primary language is correctly identified.

Headings follow a logical hierarchy. Sections and content are organised meaningfully. Lists and tables use an appropriate semantic structure. The reading order corresponds to the intended meaning.

Tool

Browser accessibility inspector, browser developer tools, document accessibility checker, document reading-order tools, screen reader.

Result

The structure, metadata, semantics and reading order are understandable without relying solely on visual presentation.

3. Colour and contrast

Check that content remains perceivable and that information is not conveyed through colour alone.

puis explications de comment tester efficacement avec des onglets par techno

Procedure

Identify text, backgrounds, icons, controls, focus indicators and graphical elements whose visibility depends on colour or contrast.

Check information conveyed by colour, such as errors, selection, status, required fields or links. Check relevant states in supported colour themes, including light and dark modes where applicable.

Verify

Text has sufficient contrast against its background. Interactive components and meaningful graphical elements have sufficient contrast where required.

Focus indicators are clearly visible. Important information is not conveyed through colour alone. Error, selected, active and disabled states remain distinguishable.

Tool

Colour Contrast Analyser , browser accessibility tools, document accessibility tools, and manual visual inspection.

Result

Required contrast levels are met and information remains understandable without relying on colour perception alone.

4. Text resizing, reflow and orientation

Check that content remains readable and usable when text or display settings are enlarged or the device orientation changes.

Que se passe t il si vous avec besoin de grossir la taille des caractères ?

QCM

puis explications de comment tester efficacement avec des onglets par techno

Procedure

Increase text size and zoom the content using the relevant browser, operating system, mobile or document settings. Test the interface at increased text sizes and, where applicable, at 200% zoom.

For web content, test reflow at a narrow viewport, including approximately 320 CSS pixels where applicable. On mobile devices, test supported portrait and landscape orientations.

Verify

Text remains readable. Content reflows without inappropriate two-dimensional scrolling, except where two-dimensional presentation is essential, such as certain complex tables.

Buttons, fields, menus, tables and other functionality remain usable. No important content is clipped, hidden or overlapped.

Content remains available in supported orientations unless a specific orientation is functionally required.

Tool

Browser zoom, browser responsive mode, Android text-size settings, iOS Dynamic Type, device orientation settings, document zoom.

Result

Users can access and operate the complete experience when text is enlarged, the viewport changes or the device orientation changes.

5. Keyboard and sequential navigation

Check that the complete experience can be navigated in a logical order without traps.

Procedure

Navigate through the complete interface using a keyboard, sequential navigation mechanism or equivalent assistive input. Move through interactive elements, content regions and controls.

Test forward and backward navigation and attempt to leave every component. For non-standard components, verify that keyboard interaction and focus behaviour are explicitly defined.

Verify

Navigation order is logical and predictable. All required interactive elements can be reached. Focus remains visible and moves in an expected order.

No component traps the user. Components do not require mouse hover to expose essential information or functionality.

Tool

Keyboard, TalkBack, VoiceOver, Switch Access, Switch Control, and document navigation tools.

Result

The complete experience can be navigated in a logical order without a keyboard, focus or sequential navigation trap.

6. Interactive elements and touch targets

Check that interactive elements can be reached, identified and operated using different input methods.

Quand utiliser un lien et un bouton

QCM

puis explications de comment tester efficacement avec des onglets par techno

Procedure

Test buttons, links, fields, tabs, menus, checkboxes, radio buttons, sliders and other interactive controls.

Verify that links and buttons are used consistently: links navigate to a destination, while buttons perform an action.

On touch devices, check the size and spacing of touch targets. Test gestures and verify that an accessible alternative is available when a specific gesture is not essential.

Verify

Every required interactive element can be reached and operated. Links and buttons have appropriate semantics and behaviour.

Touch targets have sufficient size and spacing for the applicable platform requirements. Interaction does not rely exclusively on precise touch, pointer movement or a visual interface.

Non-standard components provide an equivalent accessible way to perform their function.

Tool

Keyboard, touch device, accessibility inspector, screen reader, Switch Access, Switch Control.

Result

All required interactions can be completed using an appropriate input method without relying exclusively on touch, pointer precision or visual interaction.

7. Accessible names, roles and states

Check that assistive technologies can correctly identify controls, their purpose and their current state.

Procedure

Inspect and navigate interactive components. Check their accessible name, role and state.

Check all relevant component states, including default, hover, focus, active or pressed, selected, checked, expanded, collapsed, disabled, error, success and loading.

Pay particular attention to custom components and icon-only controls.

Verify

Each interactive element has a meaningful accessible name and an appropriate role. Its current state and relevant properties are correctly exposed to assistive technologies.

Visible labels and accessible names are consistent. Repeated controls have sufficiently specific and distinguishable names. Decorative elements are not unnecessarily exposed.

Tool

Browser accessibility inspector, Android accessibility tools, iOS accessibility tools, document accessibility checker, screen reader.

Result

The purpose, role, name and current state of every relevant component are correctly communicated to the user.

8. Forms and error handling

Check that users can understand, complete and correct forms.

Remplissez ce formulaire pour passer à la suite:

Formulaire non accessible avec des gestion d'erreur

Bonton continuer

puis explications de comment tester efficacement avec des onglets par techno

Procedure

Navigate through all form fields. Check that each field has a visible, relevant label located close to the field.

Check required fields, instructions, expected input formats and autocomplete information where applicable. Verify that required fields are identified using text or a clearly explained convention such as an asterisk.

Submit the form with missing, invalid and incorrect data. Check how validation errors are presented and announced.

Verify

Every field has a meaningful visible label and accessible name. A placeholder is not used as the only label.

Required fields and expected input formats are understandable. Errors identify the affected field and clearly explain the reason for the error.

Error messages are programmatically associated with their fields and dynamically communicated when necessary. Users can identify and correct errors.

Tool

Browser accessibility inspector, mobile accessibility tools, document accessibility checker, screen reader, and manual testing.

Result

Users can identify every field, understand what information is expected, detect errors, understand their cause and correct them successfully.

9. Links, tables and lists

Check that common content structures and navigation elements are understandable independently of their visual presentation.

Procedure

Navigate through all links and review their accessible names. Check whether repeated links can be distinguished from one another.

Inspect lists and tables in web pages, mobile interfaces and documents. For tables, check headers, relationships and reading order. For lists, check that list items are correctly identified.

Verify

The destination or purpose of each link is clear. Link and action labels are meaningful and distinguishable.

Lists are exposed as lists with the correct items. Tables have meaningful headers and relationships between headers and data can be understood.

Complex structures do not lose their meaning when read linearly or through assistive technology.

Tool

Screen reader, browser accessibility inspector, browser developer tools, document accessibility checker, and document reading-order tools.

Result

Links, lists and tables remain understandable and usable without relying on visual layout or surrounding visual context.

10. Dynamic content and media

Check that changes, notifications, status messages, animations and multimedia remain accessible and controllable.

Procedure

Trigger notifications, alerts, validation messages, status changes, loading states and other dynamic content updates. Check whether important changes are communicated without unexpectedly moving focus.

Test videos, audio, carousels, animations and other moving or changing content. Check that users can pause, stop or otherwise control automatically moving or playing content when required.

Check multimedia alternatives, including captions, transcripts and audio descriptions where applicable.

Verify

Important dynamic changes and feedback are perceivable and communicated to assistive technologies. Context changes are understandable.

Automatically moving, playing or updating content does not prevent users from accessing or controlling information. Multimedia has accessible controls and appropriate alternatives.

Content does not introduce inaccessible flashing or other harmful or distracting behaviour.

Tool

Screen reader, accessibility inspector, browser developer tools, mobile accessibility tools, document accessibility tools, and manual testing.

Result

Relevant changes, feedback and multimedia information are available to the user at the appropriate time and can be controlled when necessary.

11. Assistive technology support

Check the complete user experience with the assistive technologies relevant to the platform and content type.

Procedure

Perform the main user scenarios from start to finish using appropriate assistive technologies.

For web content, test with desktop and mobile screen readers. For mobile applications, test the platform screen reader and alternative input methods. For documents, navigate the complete document and verify that its structure and content remain understandable.

Verify

Users can identify where they are, understand the available actions, navigate between relevant elements, operate controls, understand changes and complete the main scenarios.

The interface or document provides clear navigation, meaningful feedback and predictable interaction. No inaccessible custom component, missing information, incorrect reading order or unexpected focus prevents completion of the workflow.

Tool

NVDA, JAWS , TalkBack , VoiceOver , Switch Access, Switch Control, keyboard, and document accessibility tools.

Result

The main user scenarios can be completed with the relevant assistive technology without an accessibility blocker.
